# データ鮮度・銘柄カバー率の運用

## 判定対象

「銘柄カバー率」は用途ごとに分けて扱う。

| データ | 母集団 | 主な判定 |
|---|---|---|
| 銘柄マスター | J-Quants `/equities/master` | 3,000行以上、コード重複なし、最新日が120日以内 |
| 日次価格 | `TOPIX Small 1`、`TOPIX Small 2`、`TOPIX Mid400` | 95%以上がそろう最新の代表取引日が7日以内、当日の対象銘柄の95%以上 |
| 配当財務 | 最新銘柄マスター | 最新取得試行が7日以内、開示日はプラン遅延84日＋猶予21日以内、財務行がない銘柄にも取得試行あり |

日次シグナルは設計上、全上場銘柄ではなく上記3区分だけを対象とする。したがって、
全上場銘柄数と日次取得数の単純比較は日次フローの欠損率にならない。配当フローは
銘柄マスター全体を巡回するが、開示データが存在しない銘柄もあるため、行の有無と
取得試行の有無を分離する。

限定再取得などで一部銘柄だけに翌営業日の行が入る場合があるため、単純な
`MAX(prices.date)`はカバー率の基準日にしない。直近31日から95%以上がそろう最新日を
代表取引日とし、それより新しい部分取得日は別項目として報告する。

## コマンド

読み取り専用のローカル監査:

```powershell
python scripts\audit_data_coverage.py --as-of 2026-09-14
```

J-Quantsから取得するドライラン（外部読み取り、DB変更なし）:

```powershell
python scripts\refresh_listed_info.py --as-of 2026-09-14
```

検証済みバックアップ後の適用:

```powershell
python scripts\refresh_listed_info.py `
  --as-of 2026-09-14 `
  --apply `
  --backup-verification "<verification-json>"
```

適用時はバックアップJSONが現在のDBパス・サイズ・更新日時と一致し、元DBと一時復元DBの
検証が成功していなければ拒否する。更新後に監査を再実行し、新規銘柄の価格未取得と
配当財務の未試行を次の定期処理で追跡する。

限定した価格未取得銘柄を再照会する場合:

```powershell
python -m src.update_yfinance --lookback-days 14 `
  --code 212A0 `
  --code 83030
```

`--code`を省略した場合だけ、通常の日次戦略対象全体を取得する。

銘柄コード移行により旧コードへ新銘柄の価格が保存された場合は、まずドライランで
対象件数とSHA-256を固定する。適用には、その値と現在のDBに一致する復元検証済み
バックアップがすべて必要になる。

```powershell
python scripts\repair_price_code_transition.py `
  --source-code 44490 `
  --target-code 590A0 `
  --cutoff-date 2026-06-29
```

## 解釈上の注意

- 95%は「戦略対象の日次価格」の運用下限であり、全上場銘柄の取得目標ではない。
- 銘柄マスターもFreeプランでは12週間遅延するため、上場直後の銘柄をリアルタイムに
  網羅する保証はない。
- シグナル件数は売買条件を満たした結果であり、データ取り込みカバー率ではない。
- 全上場銘柄への日次戦略拡大はAPI負荷、計算時間、戦略の再検証を伴う別の仕様変更として扱う。
