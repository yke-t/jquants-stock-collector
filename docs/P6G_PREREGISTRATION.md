# P6g 資金配分検証の事前登録

登録日: 2026-09-13

この文書は、P6gの結果を見る前に比較対象、仮説、判定基準を固定するものです。
目標CAGRへ合わせた事後的な条件追加や、同じOOS結果を見ながらの閾値調整は行いません。

## 診断課題

P6f修正後も、100株単元では購入価格の丸めにより現金が残ります。現行の新規取得目標額は
常に`約定時純資産 ÷ 最大保有数`で、保有数が最大未満でも未使用現金を残り枠へ再配分しません。

検証する仮説は「残り枠へ限定的に現金を再配分すれば、100株単元を維持したまま現金滞留を減らせる」です。
収益改善は仮説の結果であり、保証や採用理由として先に仮定しません。

## 比較する資金配分

### 基準: fixed-equal-weight

```text
target_value = open_equity / max_positions
```

P6f時点の方式です。最大20銘柄なら新規取得時の目標額は約定時純資産の5%です。

### 検証案: remaining-slots-capped

```text
target_value = min(cash / open_slots, open_equity * 0.10)
```

- 残り現金を開始時の空き枠へ均等配分します。
- 新規取得額は約定時純資産の10%を上限とします。
- 10%は20銘柄均等の5%に対して最大2倍までを許す、事前固定の集中上限です。
- 上限は新規約定時に適用し、約定後の値上がりによる比率変化は強制売却しません。
- 100株単元、現金非負、最大20銘柄、取引コスト、候補順位は変更しません。

## 候補選択

候補順位は既存の`priority_score`と銘柄コード順を維持します。価格が安いこと自体をアルファとみなす
根拠がないため、購入可能性を理由に順位を入れ替えません。P6fと同様、目標額で100株を購入できない
候補だけを飛ばし、順位を保ったまま後続候補を確認します。

## 比較方法

共通条件は次のとおりです。

- DB: `stock_data.db`を読み取り専用で使用
- シグナル評価開始: 2024-01-01
- OOS期間: 2024-08-28〜2026-09-02
- fold数: 3
- 初期資金: 3,000,000円
- 最大保有数: 20
- 売買単位: 100株
- 手数料: 10bps
- スリッページ: 5bps
- データ品質除外と株式数基準: P6fと同一

主比較ではP6fで選択されたfoldパラメータを両方式へ固定し、資金配分だけの差を測ります。
副比較として、各方式で学習期間からパラメータを選び直す完全WFAも実行します。

## 採用判定

`remaining-slots-capped`は、主比較で次をすべて満たす場合だけ有効候補とします。

1. 連結OOS CAGRが`fixed-equal-weight`以上。
2. 3つのテストfoldのうち2つ以上で総収益率が改善。
3. 連結OOSと各テストfoldの最大ドローダウンがすべて-20%以上。
4. fold平均現金比率の単純平均が低下。
5. 現金非負、最大保有数、100株単元の制約違反がない。

完全WFAのCAGR 15%と最大ドローダウン-20%も報告しますが、15%到達だけを理由に採用しません。
判定に失敗した場合は基準方式を維持し、同じOOS結果へ別の上限値を当て直しません。

## 既知の限界

- 現在の`fundamentals.scalecat`を過去にも適用するサバイバーシップ・バイアスが残ります。
- 約2年のOOSと3foldだけでは、相場局面をまたぐ恒常的な優位性を確立できません。
- 10%上限はリスク管理上の設計判断であり、データから最適化した値ではありません。
- 本検証は将来収益や実運用の約定を保証しません。
