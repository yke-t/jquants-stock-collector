# ポートフォリオ・ウォークフォワード検証仕様

`src/backtest_wfa.py`は、旧バックテストの先読み約定、株式分割前後の価格基準、資金制約、
取引コスト、損益集計の問題を是正する読み取り専用の検証エンジンです。

## 実行

```powershell
python -m src.backtest_wfa --start 2016-01-01 --splits 5
```

主な引数は`--end`、`--initial-capital`、`--max-positions`、`--lot-size`、
`--commission-bps`、`--slippage-bps`、`--allocation-policy`、`--max-entry-weight`です。
結果を保存しない確認には`--no-save`を使います。
SQLiteはURIの`mode=ro`で開くため、この処理はDBを更新しません。

## 約定規則

- シグナルは各取引日の終値確定後に生成し、翌取引日の始値でのみ新規約定します。
- 始値が損切り／トレーリング水準を下回るギャップでは、到達不能な逆指値ではなく始値で決済します。
- 日中の高値は翌取引日以降のトレーリング判定に反映します。同一日の日中高値を先に見てから、
  その日の安値で決済する順序は採用しません。
- 新規約定日の損切りだけは保守的に同日の安値で判定します。
- 各WFA区間の最終取引日は終値で強制決済し、未実現損益を消失させません。
- 買いと売りの双方にスリッページと手数料を適用します。

## 株式数基準とデータ品質

`src/price_basis.py`がJ-Quantsの明示的な`adjustmentfactor`をイベント係数として使い、
OHLCを最新の株式数基準へそろえます。係数を推測することはありません。係数が不正、OHLCが不正、
または係数のない前日比30%以上の断絶がある銘柄は検証対象から銘柄単位で除外します。
除外数と明示的な調整イベント数は`wfa_summary.json`の`data_quality`に記録します。

## 資金と集計

- 現金残高、最大保有銘柄数、売買単位を注文前に制約します。
- 同日の候補は押し目率と銘柄コードで決定論的に順位付けします。
- 上位候補を最小売買単元で購入できない場合、その候補は新規約定枠を消費せず、
  当日の実際の新規約定数が空き枠へ達するまで後続候補を確認します。
- 日次の現金と時価を合算して資産曲線を作り、総収益率、CAGR、最大ドローダウン、
  年率ボラティリティ、ゼロ金利Sharpe、勝率を計算します。
- 取引リターンの単純加算や、平均取引リターンからの擬似年率換算は行いません。
- 既存目標のCAGR 15%以上、最大ドローダウン-20%以上に対する合否を結果JSONへ記録します。

## ウォークフォワード方式

取引日を`分割数 + 1`個の連続ブロックへ分けます。学習期間は先頭から拡大し、直後の1ブロックを
重複しないテスト期間として使います。固定された小さなパラメータ候補だけを学習期間で選び、
各テスト区間の純資産日次リターンを時系列順に連結してアウト・オブ・サンプル成績を算出します。

## 既知の制約

- 銘柄区分は`fundamentals.scalecat`の現在値を使うため、過去時点の指数構成を再現できず、
  サバイバーシップ・バイアスが残ります。
- 指値板、出来高に対する注文参加率、ストップ安での約定不能、税金はモデル化していません。
- 調整係数は取得した価格履歴の範囲に存在する明示値だけを使います。
- 本結果は検証用であり、将来収益や実運用の約定を保証しません。

## P6e原因診断

2024-01-01〜2026-09-02のP6d検証（OOSは2024-08-28開始）について、
[診断ノートブック](../notebooks/p6e_wfa_cagr_diagnosis.ipynb)でCAGR 4.57%の要因を分解しました。

- 3つのfoldで選ばれた候補の学習CAGRは最大でも1.05%で、15%目標を学習データが支持していません。
- 初期資金300万円を20枠に分けると1枠15万円です。シグナル候補機会の64.8%は、
  コスト込み100株最小単元がこの金額を上回りました。fold別平均現金比率は29.4%〜44.9%です。
- 選択パラメータを固定して1株単位にした診断でもCAGRは12.12%で、最大ドローダウンは-22.14%でした。
  単元制約は大きな感度要因ですが、単独では目標を満たしません。
- 固定パラメータ・取引コストゼロのCAGRは6.91%で、コストは副次要因です。
- 学習順位とテスト順位の相関は-0.40〜0.20で、4候補の選択はfold間で安定していません。

診断時点では、候補を`candidates[:slots]`で空き枠数に切ってから購入数量を判定していたため、
先頭候補を100株買えない場合に後続の購入可能候補へ進まない問題も確認しました。

## P6f候補走査の是正

P6fでは、購入不能候補を新規約定枠へ数えず、実際の新規約定数が空き枠へ達するまで後続候補を
確認するよう是正しました。購入済み当日中に損切りした場合も、その買い注文は従来どおり1枠分の
新規約定として数えるため、1日の新規約定上限は変えていません。

同一DB、2024-01-01〜2026-09-02、3fold、初期資金300万円、最大20銘柄、100株単元、
手数料10bps、スリッページ5bpsで再WFAした結果は次のとおりです。

- 最終資産: 3,730,622円（是正前3,282,575円）
- CAGR: 11.44%（是正前4.57%、15%目標は未達）
- 最大ドローダウン: -12.29%（-20%目標を通過）
- 勝率: 45.22%（是正前36.09%）
- 平均保有数: 17.66（是正前15.08）

旧P6dのfoldパラメータを固定した比較でもCAGRは9.13%となり、候補走査だけの是正効果を確認しました。
修正後に学習期間でパラメータを選び直した結果が11.44%です。詳細は
[P6f再検証記録](P6F_CANDIDATE_TRAVERSAL.md)を参照してください。

## P6g資金配分オプション

既定の`fixed-equal-weight`は、新規取得目標額を`約定時純資産 ÷ 最大保有数`とします。
検証用の`remaining-slots-capped`は、残り現金を開始時の空き枠へ均等配分しつつ、
新規取得額を約定時純資産の`--max-entry-weight`以下へ制限します。候補順位、100株単元、
現金非負、最大保有数は変更しません。

```powershell
python -m src.backtest_wfa `
  --start 2024-01-01 `
  --end 2026-09-02 `
  --splits 3 `
  --allocation-policy remaining-slots-capped `
  --max-entry-weight 0.10
```

10%上限を結果確認前に固定した[P6g事前登録](P6G_PREREGISTRATION.md)に従う比較では、
固定パラメータCAGRが11.44%から11.90%、fold平均現金比率の単純平均が27.74%から14.09%へ
変化し、採用条件を通過しました。一方で最大ドローダウンは-12.29%から-18.02%へ悪化しました。
完全WFAのCAGRは11.46%で15%目標に届かず、改善も小さいため、既定値は
`fixed-equal-weight`のまま維持します。詳細は[P6g評価結果](P6G_ALLOCATION_RESULT.md)を参照してください。

## 出力

`reports/wfa/`に次を出力します。このディレクトリはGit管理対象外です。

- `wfa_summary.json`: 集計値、実行条件、方法論、データ品質
- `wfa_folds.csv`: 区間、選択パラメータ、学習／テスト成績
- `wfa_equity.csv`: 連結したアウト・オブ・サンプル資産曲線
- `wfa_trades.csv`: コスト控除後のアウト・オブ・サンプル取引
